# 要件定義書

プロジェクト: Oripo（AIPO リプレース）
作成日: 2026-05-26
担当: y-teshima-ost
ステータス: **ドラフト**（社内レビュー待ち）

---

## 1. はじめに

### 1.1 背景・目的

現行グループウェア AIPO（Java/Tomcat、導入から10年以上）の老朽化・保守困難を解消するため、Next.js ベースの新システム Oripo へ置き換える。

### 1.2 スコープ

現 AIPO から移行する機能（今フェーズの実装対象）:

| 機能 | 概要 |
|---|---|
| ホーム画面 | 各ウィジェットを配置するマイページ |
| 更新情報（タイムライン） | 各機能の更新履歴を自動集約して一覧表示 |
| スケジュール | 個人・グループのスケジュール管理・設備予約 |
| ユーザー名簿 | 社内ユーザーの連絡先・プロフィール閲覧 |
| ユーザー情報管理 | 管理者によるユーザーアカウント・部署・役職の管理 |
| アクセス権限管理 | ロールベースアクセス制御（RBAC） |

現 AIPO にある以下の機能は今フェーズのスコープ外:
- 掲示板、ブログ、共有 Todo、共有フォルダ、ワークフロー、報告書、アドレス帳、伝言メモ等

### 1.3 用語定義

| 用語 | 説明 |
|---|---|
| AIPO | 現行グループウェア（Java/Tomcat製） |
| Oripo | 本プロジェクトで開発する新グループウェア |
| ロール | RBAC における権限セット（管理者が自由に作成・命名） |

## 2. 機能要件

### 2.1 ホーム画面

現 AIPO のマイページに相当。ログイン後の起点となる画面。

**要件:**
- 2カラムレイアウト（左: 情報系ウィジェット、右: カレンダー系ウィジェット）
- 左カラム: 更新情報ウィジェット、ユーザー名簿検索ウィジェット
- 右カラム: スケジュール週表示ウィジェット
- 各ウィジェットから対応機能へのリンク

**参照仕様:** `docs/01_current/specs/home.md`

---

### 2.2 更新情報（タイムライン）

各機能の更新履歴を自動集約して時系列で表示する読み取り専用フィード。

**要件:**
- ホーム画面左カラムにウィジェット表示（最新 N 件）
- 全件一覧ページ（アプリ別フィルタ・キーワード検索・ページング）
- 表示項目: 更新内容テキスト、更新者氏名、更新日時
- 各更新エントリから該当機能へリンク遷移
- 対象アプリ: スケジュール（将来的に他機能も追加可能な設計）
- 投稿・編集・削除は不可（閲覧専用）
- ACL 対象外（全ログインユーザーが閲覧可能）

**参照仕様:** `docs/01_current/specs/whatsnew.md`

---

### 2.3 スケジュール

個人・グループのスケジュール管理と設備（会議室等）の予約。

**要件:**
- 日・週・月の表示切替
- 複数ユーザーの予定を横並び比較表示
- スケジュールの登録・編集・削除
  - 件名、開始/終了日時、場所、メモ、公開/非公開フラグ
  - 参加ユーザーの選択（グループ・個人）
  - 繰り返し設定（毎日・毎週・毎月等）
  - メール通知フラグ
- 設備（会議室等）の予約と空き確認
  - 管理者が事前に設備マスタ・設備グループを登録
- CSVエクスポート・インポート
- ACL: ロールで「自分の予定」「他ユーザーの予定」「設備予約」を操作別に制御

**要求仕様（#23 より）:**
- 空いている/空いていないがひと目でわかる表示
- 空いていない時間帯はそもそも選択できないようにする
- 祝日の自動反映 ⚠️ **要確認: 祝日データの取得方法（外部API利用可否等）**

**参照仕様:** `docs/01_current/specs/schedule.md`

---

### 2.4 ユーザー名簿

社内ユーザーの連絡先・プロフィール一覧を閲覧する機能。

**要件:**
- ホーム画面にキーワード検索ボックスのみのコンパクトウィジェット表示
- 全件一覧: 氏名リスト + キーワード検索 + ページング（20件/ページ）
- 絞り込み: 部署・グループ・キーワード（氏名・ふりがな部分一致）
- 詳細表示: 氏名、ふりがな、メールアドレス、電話番号（外線・内線・携帯）、携帯メール、顔写真、部署、役職
- 閲覧専用（編集はユーザー情報管理で行う）
- ACL: ロールで一覧・詳細の閲覧可否を制御

**参照仕様:** `docs/01_current/specs/members.md`

---

### 2.5 ユーザー情報管理

管理者がユーザーアカウントを管理する機能。

**要件:**
- ユーザー一覧（部署フィルタ、ページング）
- ユーザーの有効/無効切り替え（退職者対応）
- ユーザーの新規作成・編集・削除
  - 登録項目: ログインID（変更不可）、パスワード（ハッシュ保存）、姓・名、ふりがな、メールアドレス、電話番号（外線・内線・携帯）、携帯メール、顔写真、部署（複数選択可）、役職、管理者権限フラグ
- 部署マスタ管理（追加・編集・削除・並び順変更）
- 役職マスタ管理（追加・編集・削除）
- 会社情報管理
- 管理者権限を持つユーザーのみ操作可能（ACL 対象外）

**参照仕様:** `docs/01_current/specs/user-management.md`

---

### 2.6 アクセス権限管理（RBAC）

機能ごとのアクセス権限をロール単位で管理する機能。

**要件:**
- ロールの作成・編集・削除（管理者が自由に命名）
- ロールへの権限設定（機能 × 操作の組み合わせ）
  - 操作種別: 一覧・詳細・追加・更新・削除・エクスポート
- ユーザーへのロール割り当て（複数ロール可）
- ユーザーの最終ログイン日時確認
- 管理者専用機能（ACL 対象外）

**権限設定の対象範囲:**

| 機能 | 設定対象 | 設定できる操作 |
|---|---|---|
| スケジュール | 自分の予定 | 一覧・詳細・追加・更新・削除 |
| スケジュール | 他ユーザーの予定 | 一覧・詳細・追加・更新・削除 |
| スケジュール | 設備の予約 | 追加・更新 |
| ユーザー名簿 | - | 一覧・詳細 |
| 更新情報 | - | ACL 対象外（全ユーザー閲覧可） |
| ユーザー情報管理 | - | ACL 対象外（管理者専用） |
| アクセス権限管理 | - | ACL 対象外（管理者専用） |

**参照仕様:** `docs/01_current/specs/access-control.md`

## 3. 非機能要件

### 3.1 外部公開・アクセス

⚠️ **社内確認中 (#27)**。以下は確認が取れ次第確定。

- 外部公開: 必須（現 AIPO が既に外部公開済みのため）
- アクセス方法: **Cloudflare Tunnel** を利用（VPN 不要、セキュリティ確保）
- ドメイン: Cloudflare で取得予定（年間 $10 程度）
  - ドメイン名: ⚠️ **要社内確認**
- スマホ対応: レスポンシブデザイン対応（Next.js 標準範囲内）

### 3.2 セキュリティ

- 認証: セッション管理（Next.js + サーバーサイド）
- 通信: HTTPS（Cloudflare Tunnel が自動提供）
- パスワード: ハッシュ化保存（bcrypt 等）
- RBAC による機能アクセス制御
- XSS・CSRF・SQLインジェクション対策（Next.js フレームワーク標準 + 実装レビュー）

### 3.3 サーバー・インフラ

⚠️ **社内確認中 (#26)**。以下は確認が取れ次第確定。

- OS: Ubuntu（Linux、GUI操作可能な環境）
- コンテナ: Docker（docker compose でローカル開発、本番デプロイも Docker 想定）
- イメージレジストリ: GHCR（GitHub Container Registry）

### 3.4 パフォーマンス

- 一覧ページのロード: 3秒以内（通常回線）
- 同時接続ユーザー: 社内規模（数十名程度）を想定
- ページング: 一覧は20〜30件/ページ

### 3.5 対応環境

- ブラウザ: Chrome 最新版、Edge 最新版
- デバイス: PC（必須）、スマートフォン（レスポンシブ対応）

## 4. 制約・前提条件

### 4.1 データ移行

- 現 AIPO のデータ（スケジュール・ユーザー等）を Oripo へ移行する方針
- 移行の詳細は Phase 7（移行フェーズ）で別途計画
- ユーザーID・ログインID の採番体系は変更可（移行スクリプトで変換）

### 4.2 開発・運用

- 実装は Next.js 15 / TypeScript / App Router
- CI/CD: GitHub Actions（ユニットテスト自動実行）、mainマージで GHCR へイメージ push
- テスト: Vitest（ユニット）、Playwright（E2E 手動確認）
