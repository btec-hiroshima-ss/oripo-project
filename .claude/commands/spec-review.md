作業中のブランチの仕様書をレビューしてください。

## 優先順位

1. **要件定義書**（`docs/02_requirements/requirements.md`）— 記載がある事柄はこちらが最優先
2. **AIPO 仕様**（`docs/01_current/` / AIPO ソースコード）— 要件定義書に記載がない場合に準拠
3. 両方にない場合のみ独自判断を認める（仕様書に理由を明記すること）

## 手順

**1. 対象仕様書の特定**
- `git diff develop...HEAD --name-only` で変更ファイルを確認する
- `specs/` 配下の変更された `.md` ファイルを対象とする

**2. 要件定義書の確認**
- `docs/02_requirements/requirements.md` を読み、対象機能に関する記述を確認する
- 記載のある事柄は要件定義書の内容に従っているか確認する

**3. AIPO 仕様の確認**
- 要件定義書に記載のない点について `docs/01_current/` の調査資料を参照する
- 必要に応じて AIPO ソースコード（`gh api repos/arkjun/aipo/...`）も参照する

**4. レビュー観点**
- 要件定義書の記述と仕様書が矛盾していないか
- 要件定義書に記載のない点で AIPO 仕様から逸脱している箇所があるか
- 逸脱している場合、その理由が仕様書に明記されているか
- 仕様書テンプレートの必須セクション（概要・機能要件・API・データモデル・受け入れ条件）が揃っているか

**5. 結果の報告**
- 指摘事項があればリストアップする
- 問題なければ「レビュー OK」と報告する
- 指摘があれば修正してからステップ 3（実装）へ進む
