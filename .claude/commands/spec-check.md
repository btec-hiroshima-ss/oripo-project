以下の手順でスペック・実装・テストの整合性チェックを行ってください。

## 手順

**1. 作業内容の特定**
- ブランチ名から Issue 番号・機能名を確認する
- `git diff origin/main...HEAD --name-only` で変更ファイルの一覧を取得する

**2. 関連仕様書の特定**
- `specs/` ディレクトリを確認し、変更内容に関連する仕様書ファイルを探す
- 仕様書が見つからない場合は「仕様書なし」として報告し、作成が必要か確認する

**3. 変更内容の確認**
- 変更されたソースファイル（`src/`）を読む
- 変更されたテストファイル（`*.test.ts`）を読む
- 仕様書の `## 機能要件` と `## 受け入れ条件` を読む

**4. 整合性チェック**

以下の観点で照合する：

| 観点 | チェック内容 |
|---|---|
| 仕様 → 実装 | 機能要件がすべて実装されているか |
| 仕様 → テスト | 受け入れ条件がすべてテストに反映されているか |
| 実装 → 仕様 | 仕様に記載のない実装が混入していないか |

**5. 結果の報告**

- **ズレがない場合**: 「整合性OK」と報告し、push を続行する
- **ズレがある場合**: 内容を列挙してユーザーに確認を求める

```
⚠️ 以下のズレが見つかりました：

1. [仕様 → 実装] 「〇〇機能」が実装されていない
2. [仕様 → テスト] 受け入れ条件「〇〇」のテストが不足している

対応方針を確認してください：
- 仕様書を更新する（実装が正しい場合）
- 実装・テストを修正する（仕様が正しい場合）
- 意図的なズレであれば理由をコメントに残す
```
