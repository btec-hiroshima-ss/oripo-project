対象の `src/lib/{機能名}.ts` に対して Vitest ユニットテストを生成してください。

## 手順

**1. 対象ファイルの特定**
- 引数で指定されたファイル、または現在作業中のブランチの変更ファイルから `src/lib/` のファイルを特定する
- 対応する仕様書を `specs/` から探して `## 受け入れ条件` を読む

**2. 既存テストの確認**
- `{機能名}.test.ts` がすでに存在する場合は中身を読み、重複しないようにする

**3. テストの生成方針**

```ts
// モック戦略: src/lib/ の関数が依存するDB（Kysely）をモックする
import { vi, describe, it, expect, beforeEach } from 'vitest'

vi.mock('@/lib/db', () => ({
  db: {
    selectFrom: vi.fn().mockReturnThis(),
    // 必要なメソッドチェーンをモック
  }
}))
```

- **テスト対象**: `src/lib/{機能名}.ts` の各エクスポート関数
- **モック対象**: `@/lib/db`（Kysely の `db` オブジェクト）
- **テストケース**: 仕様書の `## 受け入れ条件` を1条件1テストに対応させる
- **ファイル配置**: テスト対象と同じディレクトリ（`src/lib/schedule.ts` → `src/lib/schedule.test.ts`）

**4. テストケースの構造**

```ts
describe('関数名', () => {
  beforeEach(() => {
    vi.clearAllMocks()
  })

  it('受け入れ条件の文言をそのままテスト名にする', async () => {
    // Arrange: モックの戻り値を設定
    // Act: 関数を呼び出す
    // Assert: 期待値を確認
  })
})
```

**5. 受け入れ条件がない場合**
- 仕様書が見つからない場合は「仕様書が見つかりません」と報告してユーザーに確認する
- 受け入れ条件がない場合は関数の主要な振る舞い（正常系・異常系）をカバーするテストを生成する

**6. テスト実行確認**

```bash
npm run test -- {ファイル名}
```

テストが通ることを確認してから完了を報告する。失敗した場合は原因を調査して修正する。
